# Верификационный ранбук: проверка колоды из чистого клона

> Штатный шаг после каждой колоды (`ROADMAP.md`). Выполняется **независимым**
> агентом, который кода не писал: 18.09 такой прогон нашёл четыре дефекта,
> невидимых для 583 тестов (`Head_Pains.md` 2.14), за двадцать минут.
>
> Ниже — образец с колоды безголовой поверхности. Разделы 0–1, 5 и 6 годятся
> как есть; 2–4 переписываются под предмет очередной колоды.


Цель — **доказать или опровергнуть**, что новые возможности работают в том виде,
в каком они описаны в документации. Не «посмотреть, что всё хорошо», а
попытаться поймать несоответствие.

## Правила

1. Работать **только** в каталоге клона. Ничего не коммитить, никуда не пушить.
2. **Ничего не чинить.** Нашёл расхождение — записал и пошёл дальше. Чинить — не
   твоя работа в этом прогоне.
3. Для каждого шага записать **ОЖИДАЛОСЬ** и **ПОЛУЧЕНО** (вывод дословно,
   обрезанный до существенного). Шаг без фактического вывода не считается.
4. Мутационные шаги (раздел 5) обязательно откатывать через `git checkout -- <файл>`
   и после отката убеждаться, что тесты снова зелёные.
5. Сети к провайдеру нет и `.env` отсутствует — так и задумано. Всё, что требует
   реального батча, проверяется через подставные бэкенды в тестах и через
   поведение на ошибках.

## 1. Безголовый контракт: stdout всегда один JSON

Главное правило конструкции (`TASK_headless.md`, раздел B). Каждый вызов ниже
проверить на: `stdout` парсится как JSON (`| venv/bin/python -m json.tool`),
код возврата совпадает, человеческий лог в stdout **не течёт**.

| # | команда | ОЖИДАЛОСЬ |
|---|---|---|
| 1.1 | `venv/bin/mrph deck status` | JSON, exit 0 |
| 1.2 | `venv/bin/mrph deck status --pretty` | тот же JSON с отступами, exit 0 |
| 1.3 | `venv/bin/mrph deck check` | JSON с ключами `cards`, `errors`, `warnings`, `hazards`; exit 0 |
| 1.4 | `venv/bin/mrph report` | JSON (архивные прогоны в репозитории есть) или внятная JSON-ошибка |
| 1.5 | `venv/bin/mrph deck add --file /нет/такого.json` | `{"error":{"code":4,...}}`, exit 4 |
| 1.6 | `venv/bin/mrph frobnicate` | `{"error":{"code":4,"kind":"UsageError",...}}`, exit 4 |
| 1.7 | `printf 'не json' > /tmp/bad.json && venv/bin/mrph deck add --file /tmp/bad.json` | JSON-ошибка, ненулевой код |
| 1.8 | `printf '/quit\n' \| venv/bin/mrph` | запускается REPL (баннер), НЕ JSON |

**Отдельно 1.9:** убедиться, что безголовый путь не тянет консольного бота:

```bash
venv/bin/python -X importtime bin/mrph deck status 2>&1 | grep -c "flows.morph"
```

**ОЖИДАЛОСЬ:** `0`.

## 2. Гейт владения файлами

Собрать три колоды во временном каталоге и проверить реакцию. Использовать
`mrph deck add --file` и `mrph deck check`. Между колодами чистить:
`rm -rf .morph/deck.json`.

**2.1 write-write — две карты одного поколения пишут один файл.** Ожидается
**отказ** прогона: `mrph deck check` покажет `errors >= 1` и hazard вида
`write-write`. Карты (подставить в JSON-массив):

```json
[{"custom_id":"a","intent":"generate","target":"util.py","context_slice":["README.md"],"instruction":"x"},
 {"custom_id":"b","intent":"generate","target":"util.py","context_slice":["README.md"],"instruction":"y"}]
```

**2.2 read-write — карта читает то, что пишет сосед.** Ожидается hazard
`read-write` со `severity: error`, **починяемый**: в нём должно быть видно, кто
читатель, кто писатель.

```json
[{"custom_id":"writer","intent":"generate","target":"util.py","context_slice":["README.md"],"instruction":"x"},
 {"custom_id":"reader","intent":"generate","target":"app.py","context_slice":["util.py"],"instruction":"y"}]
```

**2.3 пустой срез.** Карта с `"context_slice":[]` рядом с другой картой →
ожидается **предупреждение** `implicit-read`, а не ошибка: `errors: 0`,
`warnings >= 1`.

## 4. Устойчивое ожидание — что именно оно повторяет

Прочитать `cards/cli_wait.py` и подтвердить фактами из кода:

- список `PERMANENT` — что именно **не** повторяется;
- отступ: старт и потолок;
- по каким часам считается бюджет (важно: монотонные не тикают во сне).

**ОЖИДАЛОСЬ:** повторяется всё, кроме `KeyboardInterrupt`, `SystemExit`,
`MemoryError`; отступ 5→120 с; `time.monotonic`. Если расходится с
`README_Morph2.md` §12 — это находка.

## 5. Мутационные проверки: тесты не полые

Самая важная часть. Каждая мутация: внести, прогнать **указанный** файл тестов,
убедиться, что он **упал**, откатить, убедиться, что снова зелено.

| # | что сломать | чем проверять | ОЖИДАЛОСЬ |
|---|---|---|---|
| 5.1 | в `cards/hazards.py` в `find_hazards` убрать добавление hazard'а `KIND_WRITE_WRITE` | `pytest tests/test_hazards.py -q` | упало |
| 5.2 | в `cards/compiler.py` в `CompiledInputs.changed` вернуть `[]` всегда | `pytest tests/test_stale_context.py -q` | упало |
| 5.3 | в `cards/cli_wait.py` дописать в `PERMANENT` класс `Exception` | `pytest tests/test_cli_wait.py -q` | упало |
| 5.4 | в `cards/acceptance.py` в `verify_card` убрать откат (`_restore_originals`) в ветке провала | `pytest tests/test_acceptance.py -q` | упало |

Если какая-то мутация **не роняет** тесты — это находка первого класса: код не
покрыт, и зелёная приёмка ничего не значит.

## 6. Что проверить нельзя и почему

Записать явно: `submit`, `collect --wait`, `run` требуют настроенного провайдера
(`.env` отсутствует). Проверить только их **поведение на отсутствии
процессора**: вызов должен вернуть JSON-ошибку и ненулевой код, а не трейсбек.
