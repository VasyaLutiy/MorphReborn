## 1. Зачем это

Ночная колода 19.09 научила Морфа держать ночь: прогон переживает обрыв, не
сжигает попытки на нечитаемом диагнозе и имеет предел. Но держит он её **на
машине оператора**. Осталось шесть препятствий, и каждое уже стоило чего-то
измеренного:

| препятствие | цена, замеренная |
|---|---|
| диагноз упавшей попытки не доживает до архива | карта `run-budget-wiring` прошла со второй попытки, и почему упала первая — узнать уже нельзя. Утром у оператора нет ничего (боль 2.15) |
| бюджет не спрашивают перед перегенерацией | предел судится только на границе поколения; три попытки внутри отработают молча (боль 2.16) |
| безголовый путь не умеет пул | `mrph run --processor` берёт один id; ферма локальных узлов ночью недоступна, конкурентность пришлось собирать драйвером поверх библиотеки (боль 2.17) |
| реестр подхватывает облачный слот из окружения | стенд объявил 8 локальных узлов, `registry.ids` вернул 9: девятым пришёл `openai` из `AZURE_OPENAI_API_KEY` в оболочке. Библиотечный пул отправил бы часть карт к невыбранной модели (боль 3.6) |
| `venv/bin/mrph` — копия, а не ссылка | `setup.py` копирует `bin/mrph`; после самоправки установленная команда остаётся вчерашней, и автономный контур замыкается на ручную переустановку |
| прогон некуда унести с ноутбука | ноутбук засыпает, cron его не будит; 18.09 сон уронил соединение на 23-й минуте |

Число, по которому будут судить: **прогон, запущенный не с машины оператора,
доводит колоду до ветки в origin**. Всё остальное — средства.

## 2. Контракт: что должно стать правдой

### 2.1. Формы данных на ВХОД

Каждая форма, которую код обязан **построить или разобрать**, и модуль с её
определением. Модуль обязан попасть в срез карты, которая эту форму строит.

| форма | где определение | реальный образец |
|---|---|---|
| исход карты | `cards/generations.py` (`CardOutcome`, поля включая `earlier_failures`, `acceptance_output`, `attempts`) | `.morph/runs/*/report.json` |
| сериализация исхода | `cards/store.py` (`_outcome_to_dict`, `_outcome_from_dict`) | там же |
| пределы прогона | `cards/budget.py` (`RunBudget`, `BudgetLedger`, `BudgetExceeded`, `STATUS_BUDGET_EXCEEDED`) | — |
| путь перегенерации | `cards/generations.py` (`process_generation`, блокирующий цикл повторов; счёт батчей через `batch_ids`) | — |
| конфигурация процессора | `processors/registry.py` (`ProcessorConfig`, `ProcessorRegistry.from_env`, `_add_namespaced`, `_add_legacy`, `batch`, `batch_pool`) | `.env` рядом с репозиторием |
| батч-бэкенд | `processors/batch.py` (`BatchBackend`: `submit`/`status`/`collect`; `LocalBatchBackend(registry, ids)`) | там же |
| разбор командной строки | `cards/cli.py` (`_build_parser`, `_handler`), `cards/cli_backend.py` (`resolve_backend`) | `mrph --help` |
| установка пакета | `setup.py` (`scripts=["bin/mrph"]`, `py_modules`), точка входа `bin/mrph` | `venv/lib/*/site-packages/mrph-*.dist-info` |
| задание раннера | схема GitHub Actions workflow (`on`, `jobs.<id>.steps`, `permissions`) | ни одного workflow в репозитории пока нет |

**Фикстура домена — копия реального артефакта.** Нужен в тесте отчёт или
колода — берите valid из `.morph/runs/*/`.

### 2.2. Формы данных на ВЫХОД

1. **Исход карты в архиве получает `earlier_failures`** — той же формы, что поле
   в `CardOutcome` (строка или `None`). Второй сериализации исхода не заводить:
   и `state.json`, и `report.json` пишет `_outcome_to_dict`. Чтение — через
   `.get`, чтобы отчёты, записанные раньше, продолжали читаться.
2. **Отказ по бюджету перед перегенерацией** выглядит ровно как отказ на границе
   поколения: `STATUS_BUDGET_EXCEEDED` и `reason`, называющий предел и оба числа.
   Новых статусов не заводить.
3. **Пул в безголовом пути**: `resolve_backend` возвращает ту же пару
   `(backend, label)`, что и сегодня; для нескольких узлов `label` — их id через
   `+`, как уже делает REPL. Новой формы метки не заводить.
4. **Workflow** пишет в `$GITHUB_STEP_SUMMARY` одну строку итога — ту же, что
   `cards.notify.build_run_message`, без второй сборки текста.

### 2.3. Имена

| что | имя |
|---|---|
| поле исхода в архиве | `earlier_failures` (уже существует в `CardOutcome`) |
| точка запроса бюджета | перед сабмитом батча перегенерации, внутри `process_generation` |
| пул в безголовом пути | `--processor` принимает список через запятую и `@all`; `@all` означает «все локальные узлы» |
| фильтр пула | `ProcessorRegistry.batch_pool` принимает только `kind in ("llama_cpp", "ollama")` и отказывает на смешанном списке |
| модуль точки входа | `mrph_main.py` в корне, функция `main()` — то, что сегодня делает `bin/mrph` |
| объявление установки | `entry_points={"console_scripts": ["mrph = mrph_main:main"]}`, `scripts=` уходит |
| файл задания | `.github/workflows/nightly-deck.yml`, job `deck` |
| вход задания | `deck` — путь к `decks/<deck-id>.json` в репозитории; `processor` — id из секретов |

### 2.4. Что нельзя сломать

- **674 теста остаются зелёными.**
- `bin/mrph` продолжает работать как скрипт: `entry_points` добавляется, ручной
  запуск `venv/bin/python bin/mrph` не ломается.
- Безголовый stdout остаётся JSON: один документ на вызов, прогресс — в stderr.
- Коды выхода: `0` штатно, `2` отказ постановки, `3` исчерпан бюджет ожидания.
- `--processor` с одним id ведёт себя ровно как сегодня.
- Ключи `report.json` не переименовываются; добавляется ровно один.
- Правило «одна модель на колоду»: пул из разных `kind` — отказ, а не молчаливое
  смешение.
- **Докстринги и комментарии сохраняются дословно.**

## 3. Приёмка

Базовая линия: **674 теста** на `8738023`.

Форма критерия для карты, правящей существующий файл, — ступенчатая, от узкого к
широкому, потому что в перегенерацию уезжает вывод **первого** упавшего звена:

```
<свой тест -q --tb=line> && <тесты задетых модулей -q --tb=line> && venv/bin/python -m pytest -q --tb=line && <страж прозы>
```

Стражи прозы, числа сняты с `8738023`:

| файл | строк | вхождений `"""` |
|---|---|---|
| `cards/store.py` | 1688 | 86 |
| `cards/generations.py` | 1396 | 64 |
| `cards/cli.py` | 314 | 18 |
| `cards/cli_backend.py` | 152 | 10 |
| `cards/cli_cycle.py` | 280 | 6 |
| `processors/registry.py` | 301 | 18 |
| `processors/batch.py` | 785 | 54 |

Приёмки по областям:

1. **Диагноз в архиве.** Критерий должен доказать круг: исход с непустым
   `earlier_failures`, записанный и прочитанный обратно, сохраняет поле дословно;
   отчёт, записанный без этого поля (старый формат), продолжает читаться.
2. **Бюджет перед перегенерацией.** Критерий должен доказать, что прогон,
   которому осталось меньше перегенераций, чем требует упавшая карта, **не
   отправляет** батч повтора: бэкенд, роняющий исключение на `submit`, не
   вызывается вовсе, а карта получает `budget-exceeded` с числами. Часы
   фальшивые.
3. **Пул в безголовом пути.** Критерий должен доказать, что `--processor` со
   списком из двух локальных узлов даёт один бэкенд с двумя слотами и метку из
   обоих id, а один id ведёт себя как сегодня.
4. **Фильтр пула.** Критерий должен доказать, что пул, которому дали облачный и
   локальный узел вместе, **отказывает** с диагнозом, называющим оба, а не
   собирает смесь. И что список, собранный из окружения с посторонним
   `AZURE_OPENAI_API_KEY`, не превращается молча в пул с облачным слотом.
5. **Установка.** Критерий должен доказать на **настоящей установке**, а не на
   тексте `setup.py`: во временном venv `pip install .` кладёт исполняемый
   `mrph`, который не является побайтовой копией `bin/mrph`, и `mrph deck` в
   пустом каталоге отвечает валидным JSON. Это минуту времени, и она того стоит:
   предыдущая редакция спеки объявила эту область недоказуемой локально — ошибка
   автора, установка проверяется тривиально.
6. **Задание раннера.** Критерий должен доказать структуру, а не поведение:
   файл разбирается как YAML, объявляет `permissions: contents: write`, ставит
   версию питона явно, не содержит ключей в открытом виде и называет шаги
   установки, прогона и пуша ветки. **Настоящая проверка — первый прогон на
   раннере, и она человеческая**, потому что раннер доказывается раннером.

## 4. Ограничения

1. **Конверт правки существующего файла — 20–60 строк.** Не влезает — делить
   карту. *19.09 правило сработало заранее и не было применено: карта на
   `generations.py` пришла с +65 и оказалась единственной, потребовавшей
   перегенерации.* Считайте конверт гейтом, а не пожеланием.
2. **Карта аддитивна.** Удаления — красный флаг.
3. **Код и его тест — одной картой** через `targets`.
4. **Один файл — одна карта-владелец в поколении.**
5. **Срез называть явно.**
6. **Широкая карта едет с `variants: 2`** и ступенчатой приёмкой: падение
   предсказуемо заранее, второй сэмпл едет тем же батчем и очереди не добавляет.
7. **Файл, который пишет карта поколения, не появляется в срезах её соседей** —
   иначе `failed (stale-context)`.
8. **Починка не действует на текущий прогон**: модули загружены в память при
   старте. Ставить область глубиной ради того, чтобы ею воспользовались соседи,
   бессмысленно.

## 6. Что намеренно НЕ задано

Разбивка на карты, их число и границы, срезы, порядок и поколения, формулировки
приёмочных команд, имена тестовых файлов, выбор между `targets` и картой-судьёй.

## 7. Что вне области этой колоды

- **Учёт денег.** Морф не записывает счёт провайдера ни в состояние, ни в отчёт;
  бюджет считает карты, перегенерации и время, но не доллары. Отдельная работа.
- Параллельные колоды и очередь слияний; `mrph plan --spec`; перекройка MCP;
  праймер холодного старта.
- Секреты и защита `main` в репозитории — ручная настройка оператора; колода
  только пишет задание.
- Сам первый прогон на раннере: его запускает человек и он же читает результат.
