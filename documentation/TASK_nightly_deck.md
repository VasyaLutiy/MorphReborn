## 1. Зачем это

Колода должна уходить вечером, а утром лежать в ветке. Сегодня она этого не
делает, и каждое препятствие уже оплачено прогоном:

| препятствие | цена, замеренная |
|---|---|
| обрезка диагноза режет причину | обрез 4000 символов пришёлся на `intent must be one of `; карта `cli-run-cycle` сожгла все три попытки, каскадом ушли две зависимые, восстановительный прогон стоил трёх лишних поколений (боль 2.13) |
| `/collect wait` в REPL рвётся от одной потери соединения | `ConnectionResetError` на 23-й минуте; до этого `RuntimeError: timed out` после 1 ч 42 мин ожидания. В безголовом пути починено, в REPL нет (боль 2.5) |
| заказ на незавершённые карты нигде не лежит | `.morph/deck.json` под `.gitignore`; смерть машины посреди прогона оставляет принятые карты закоммиченными, а незавершённые — нигде (боль 2.6) |
| у прогона нет предела | зациклившаяся перегенерация тратит деньги молча; wall-clock не ограничен ничем, кроме шестичасового бюджета ожидания |
| состояние прогона не наблюдаемо | оператор узнаёт исход, вернувшись к терминалу; ночью это значит «утром» |

Числа, по которым будут судить результат: **три сожжённые попытки → ноль**,
**один обрыв связи → ноль прерванных ожиданий**, **603 теста → больше 603**.

## 2. Контракт: что должно стать правдой

### 2.1. Формы данных на ВХОД

Каждая форма, которую код обязан **построить или разобрать**, и модуль, где
лежит её определение. Модуль обязан попасть в срез карты, которая эту форму
строит — правило, оплаченное тремя сожжёнными попытками 18.09.

| форма | где определение | реальный образец |
|---|---|---|
| морф-карта | `cards/schema.py` (`MorphCard`, допустимые `intent`) | `.morph/runs/*/deck.json` |
| состояние прогона | `cards/store.py` (`DeckStore._default_state`, `begin_run`): ключи `deck_id`, `generations`, `branch`, `backend_label` | `.morph/runs/*/state.json` |
| отчёт прогона | `cards/store.py` (`record_run`): ключи `deck_id`, `completed_at`, `branch`, `backend_label`, `generations`, `batch_ids`, `outcomes` | `.morph/runs/20260918-150640-34c1caaf/report.json`, 2.2 КБ |
| исход карты | тот же `report.json`, `outcomes[<custom_id>]`: `custom_id`, `status`, `paths`, `reason`, `attempts`, `winning_variant`, `acceptance_*` | там же |
| протокол бэкенда | `processors/batch.py` (`BatchBackend`): `submit(requests) -> str`, `status(batch_id) -> str`, `collect(batch_id) -> Dict[str, Optional[str]]` | `LocalBatchBackend` в том же файле |
| обёртка устойчивости | `cards/cli_wait.py` (`ResilientBackend(backend, *, timeout, log, sleep, now)`, `wait_until`, `WaitTimeout`) | — |
| вывод приёмки | `cards/acceptance.py` (`clip_output`, `_OUTPUT_TAIL_CAP = 4000`, маркер элизии) | — |

**Фикстура домена — копия реального артефакта, а не сочинение.** Нужна в тесте
морф-карта или отчёт — берите валидный из `.morph/runs/*/`, тогда знание формата
не требуется вовсе.

### 2.2. Формы данных на ВЫХОД

1. **Заказ в git.** Колода, положенная в репозиторий при старте прогона,
   переиспользует **ту же сериализацию**, что архивный `deck.json`
   (`cards/store.py`, `archive_run`). Второй формы колоды быть не должно.
2. **Бюджет прогона** — одна структура с тремя пределами (см. имена ниже).
   Превышение любого предела завершает прогон **штатно**: незавершённые карты
   получают исход со `status`, читаемым как отказ по бюджету, и `reason`,
   называющим предел и число. Это не исключение наружу и не `sys.exit`.
3. **Сообщение нотификатора** — одна строка, и **в ней числа**: id колоды, ветка,
   принято/провалено/пропущено карт, поколений, минут. Без чисел сообщение
   бесполезно: оператор всё равно пойдёт смотреть.
4. `report.json` ключей не меняет и второй сериализации не заводит.

### 2.3. Имена

| что | имя |
|---|---|
| модуль бюджета | `cards/budget.py` |
| структура пределов | `RunBudget` с полями `max_cards`, `max_regenerations`, `deadline_seconds` |
| отказ по бюджету | `BudgetExceeded`, статус исхода `budget-exceeded` |
| флаги безголового прогона | `--max-cards`, `--max-regenerations`, `--deadline` |
| каталог заказов в репозитории | `decks/`, файл `decks/<deck-id>.json` |
| модуль нотификатора | `cards/notify.py` |
| точки нотификатора | `build_run_message(report) -> str`, `send_notification(message, command=None) -> bool` |
| канал нотификатора | переменная окружения `MORPH_NOTIFY_CMD`; команда получает сообщение на stdin |
| устойчивость REPL | своих имён не заводит: `/collect wait` берёт `cards.cli_wait.ResilientBackend` и `COLLECT_WAIT_TIMEOUT_SECONDS`, которые уже есть |

### 2.4. Что нельзя сломать

- **603 теста остаются зелёными.** Это базовая линия, а не пожелание.
- Безголовый stdout остаётся JSON: один документ на вызов, прогресс — в stderr.
- Коды выхода: `0` штатно, `2` отказ постановки, `3` исчерпан бюджет ожидания.
- Трейлеры провенанса в коммитах карт: `Morph-Card`, `Morph-Model`,
  `Morph-Acceptance`, `Morph-Acceptance-Exit`.
- `/collect` без `wait` — по-прежнему ровно один опрос.
- Ключи `report.json` не переименовываются.
- **Докстринги и комментарии сохраняются дословно.** Исполнитель возвращает файл
  целиком; тесты структурно слепы к вычищенной прозе (боль 4.2).

## 3. Приёмка

Базовая линия: **603 теста** на `2a6618e`.

Обязательная форма критерия для карты, правящей существующий файл:

```
<проверка нового поведения, -q --tb=line> && venv/bin/python -m pytest -q --tb=line && <страж прозы>
```

Страж прозы — счётчик тройных кавычек в правленом файле. Базовые числа сняты с
живого дерева на `2a6618e`; берите строку своего файла:

| файл | строк | вхождений `"""` |
|---|---|---|
| `cards/acceptance.py` | 445 | 26 |
| `cards/cli_wait.py` | 320 | 26 |
| `cards/cli_run.py` | 252 | 12 |
| `cards/cli_cycle.py` | 251 | 6 |
| `cards/cli.py` | 287 | 18 |
| `cards/cli_json.py` | 251 | 12 |
| `cards/store.py` | 1628 | 84 |
| `flows/morph.py` | 1756 | 48 |

```bash
venv/bin/python -c "import sys;s=open('<файл>').read();sys.exit(0 if s.count(chr(34)*3)>=<N> else 1)"
```

Свойства критерия, каждое оплачено провалом:

- **печатает диагноз** — `assert` без сообщения сжигает три попытки вслепую;
- **печатает плотно** — `-q --tb=line`. Не косметика: на одном и том же падении
  `-q` довёз 1 диагноз из 7, `--tb=line` — 5. `--tb=no` не использовать;
- **содержит полный прогон** для правки существующего файла (правило 3);
- **проверен руками до сабмита** — команда обязана реально запускаться.

Приёмки по областям работы:

1. **Обрезка диагноза.** Критерий должен доказать, что **известная причина
   пережила `clip_output`**: на выводе, заведомо длиннее капа, с причиной,
   помещённой в середину, — причина присутствует в результате. Плюс: результат
   не превышает свой кап, маркер элизии называет точное число выброшенных
   символов, обрез не рвёт строку посередине.
2. **Устойчивость `/collect wait`.** Критерий должен доказать, что ожидание
   **переживает обрыв**: бэкенд, роняющий `ConnectionResetError` на первом
   опросе и отвечающий на втором, доводит ожидание до результата, а не до
   сообщения оператору. Часы в тесте фальшивые — реальных пауз в приёмке быть
   не должно.
3. **Заказ в git.** Критерий должен доказать, что после старта прогона (и **до**
   его завершения) колода лежит в рабочем дереве под `decks/<deck-id>.json` и
   закоммичена, а её содержимое читается тем же загрузчиком, что и архивная.
4. **Бюджет.** Критерий должен доказать все три предела по отдельности: прогон,
   упёршийся в `max_cards`, в `max_regenerations` и в `deadline_seconds`,
   завершается штатно, называет предел и число в `reason`, и не тратит ничего
   после отказа. Часы фальшивые.
5. **Нотификатор.** Критерий должен доказать, что сообщение содержит числа
   (id колоды, счётчики карт, минуты) и что отсутствие `MORPH_NOTIFY_CMD` —
   не ошибка, а тихий no-op. Транспорт в тесте фальшивый; наружу приёмка ничего
   не шлёт.

## 4. Ограничения

Общие (из шаблона, повторены здесь, потому что нарушаются именно они):

1. **Конверт правки существующего файла — 20–60 строк.** Не влезает — делить
   карту, а не расширять срез (правило 8).
2. **Карта аддитивна.** Удаления — красный флаг.
3. **Код и его тест — одной картой** через `targets`.
4. **Один файл — одна карта-владелец в поколении** (`/deck check` проверяет).
5. **Срез называть явно.** Пустой = весь проект.
6. **Ширина дешевле глубины.** Каждое поколение — отдельное стояние в очереди
   (glm: 23–38 мин) и прирост контекста оркестратора.

Два ограничения, специфичных **для этой колоды**, потому что она правит Морфа,
которым же и запускается:

7. **Файл, который пишет карта поколения, не появляется в `context_slice` её
   соседей по тому же поколению.** Иначе сосед получит `failed (stale-context)`:
   файлы, из которых его компилировали, изменились до разбора ответа. Читать
   такой файл можно только карте следующего поколения, через `depends_on`.
8. **Починка обрезки диагноза не действует на текущий прогон.** Модули загружены
   в память при старте; правка `cards/acceptance.py` на диске меняет поведение
   только следующего запуска. Ставить эту область глубиной «чтобы остальные
   карты ею пользовались» — бессмысленная трата поколения.

## 5. Приёмы, которые уже сработали

- **Чистая логика — в новый файл, в большой файл — только проводка.** Новый файл
  конвертом не ограничен. `flows/morph.py` (1756 строк) и `cards/store.py`
  (1628 строк) — файлы, где широкая карта уже роняла 14 чужих тестов.
- **Идиому карты брать из реального принятого прогона** (`.morph/runs/*/deck.json`).
- **Образец формата — настоящий артефакт**, а не производящий его код: 2.2 КБ
  `report.json` дешевле и точнее, чем `store.py` на 1628 строк.
- **Фикстура домена — копия реального артефакта.**

## 6. Что намеренно НЕ задано

Разбивка на карты, их число и границы, срезы, порядок и поколения, формулировки
приёмочных команд, имена тестовых файлов, выбор между `targets` и картой-судьёй.

> Это работа оркестратора и единственная величина, чью стоимость мы меряем.

## 7. Что вне области этой колоды

- `entry_points` вместо копирующего `scripts=` в `setup.py` — ручной шаг
  оператора: локально доказуемой приёмки у него нет, а переустановка окружения
  во время прогона запрещена.
- Прогон на GitHub Actions — отдельно и человеком: на раннере доказывается
  раннером, а не колодой.
- Параллельные колоды и очередь слияний, `mrph plan --spec`, перекройка MCP,
  праймер холодного старта.
- Пуш ветки в `origin`/`reborn` и слияние в `main` — человеческий акт утром.

## 9. Предрегистрация прогнозов

Ведётся оператором **вне этого файла** — намеренное отступление от шаблона.
Число карт и поколений, записанное здесь, заякорило бы оркестратора, который
эту спеку читает, и замер разбивки потерял бы смысл.

Здесь остаётся только то, что не якорит:

| величина | прогноз |
|---|---|
| тестов после прогона | > 603 |
| карт с исходом `stale-context` | 0 |
| конфликтов `write-write` на префлайте | 0 |

**Проверяемое утверждение:** ни одна карта не провалится по `stale-context` —
потому что ни один файл, записанный картой поколения, не лежит в срезе её
соседа по тому же поколению (ограничение 7).
