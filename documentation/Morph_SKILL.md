# Morph 2.0: руководство оркестратора

> Для того, кто занимает роль **оркестратора** — человека или агента. Если вы
> пишете код Морфа, вам нужен [`DEVELOPMENT_PLAN.md`](./DEVELOPMENT_PLAN.md).
> Если вам нужна философия — [`NEW_PARADIGN.md`](./NEW_PARADIGN.md) и
> [`batch-orchestrator.md`](./batch-orchestrator.md). Здесь — ремесло.

## Ваша роль

Вы не пишете код. Совсем. Вы производите **спецификации** — морф-карты, — а код
пишут исполнители на батч-API. Ваш вклад в промпт карты составляет около одного
процента текста (замерено: 1106 символов инструкции против 127 тысяч символов
контекста). Остальное — исходники, которые Морф подставляет сам.

Шесть вещей, которые делаете вы и не делает никто другой:

1. **Декомпозиция** цели в набор самодостаточных карт.
2. **Срез контекста** — какие файлы нужны этой карте.
3. **Критерий приёмки** — команда, отличающая сделанное от несделанного.
4. **Граф зависимостей** — что обязано ждать, а что уедет одним батчем.
5. **Бюджет** — какая модель, сколько вариантов, где это окупается.
6. **Диагноз по отчёту** — почему карта упала и что с этим делать.

Труднее всего третье. Сформулировать проверяемый критерий сложнее, чем написать
код, который его проходит.

## Морф-карта

```json
{
  "custom_id": "fix-retry-idempotence",
  "intent": "patch",
  "targets": ["cards/store.py", "tests/test_store.py"],
  "context_slice": ["cards/generations.py"],
  "acceptance": "python3 -m pytest tests/test_store.py -q && python3 -m pytest -q",
  "variants": 1,
  "depends_on": [],
  "model": null,
  "instruction": "..."
}
```

| поле | смысл |
|---|---|
| `custom_id` | имя джоба, символы `[A-Za-z0-9._-]`; по нему же зовутся файлы вариантов |
| `intent` | `generate` \| `patch` \| `todo` |
| `target` / `targets` | ровно одно из двух. `targets` — карта-changeset, пишет набор файлов атомарно |
| `context_slice` | какие файлы показать исполнителю. `[]` — весь проект |
| `acceptance` | shell-команда; **exit 0 = принято**. Без неё карта — не карта, а пожелание |
| `variants` | best-of-N: N сэмплов, побеждает первый прошедший приёмку |
| `depends_on` | карты, которые обязаны завершиться раньше; разносит по поколениям |
| `model` | хинт модели; **одна модель на батч** — колода со смесью не уедет одним батчем |
| `instruction` | что сделать и почему. Не как — «как» решает исполнитель |

**Для `patch` цель подставляется автоматически** как «Original file». В
`context_slice` её указывать не нужно — компилятор всё равно уберёт дубль.

## Семь правил, оплаченных опытом

### 1. Приёмка — и есть спецификация

Проверено на живой модели. Карте дали инструкцию «верни True для чётных» и
приёмку `assert is_even(2) is False`. Модель получила вывод упавшей приёмки и
**переписала функцию под критерий**, честно задокументировав противоречие:
«такое поведение требует приёмочная проверка модуля».

Отсюда: естественный язык инструкции — подсказка, а **проверяемый критерий —
закон**. Ошибётесь в критерии — получите уверенно-зелёный неправильный код, и
перегенерации будут старательно сходиться именно к вашей ошибке.

### 2. Автор критерия и автор кода — разные

Зелёный прогон что-то значит только тогда, когда реализация не могла подогнаться
под проверку. Практика: **тест — отдельная карта** первого поколения, код —
карта второго, зависящая от него. Так был построен MCP-сервер: конформанс-тест
писал один прогон, сервер — другой, и судья оказался строже заказчика (попросили
пять пунктов протокола, он написал семь).

### 3. У `patch`-карты в приёмке всегда есть страж регрессии

```
"acceptance": "<проверка нового поведения> && python3 -m pytest -q"
```

Исполнитель возвращает **файл целиком**. Главный риск — не «плохо написал
новое», а «молча уронил чужое». Полный прогон тестов это ловит.

*Замер:* правка файла в 1286 строк вернулась 1298 строками, все 69 символов
верхнего уровня на месте, дифф ровно в заказанном месте. Страх не подтвердился —
но проверять надо.

### 4. Меняете поведение — берите `targets`

Изменение почти всегда тянет за собой тест. Карта с одной целью такую задачу
**не может** выразить: код поправит, тест останется старым, приёмка упадёт.
Реальный случай: карта просила добавить два инструмента, а её приёмка гоняла
тест, требующий, чтобы инструментов было ровно четыре. Карта была невыполнима
по построению, и три попытки сгорели впустую.

С `targets` код и тест едут одной картой и принимаются атомарно: либо оба, либо
ни одного.

### 5. Срез контекста режьте, но не ради денег

| срез | на карту | цена карты |
|---|---|---|
| 1 файл | ~1 КБ | $0.0007 |
| 3 файла | ~35 КБ | $0.0014 |
| весь проект | ~387 КБ | $0.0083 |

Разница в цене четырёхкратная и в абсолюте ничтожная. Режьте ради **качества**:
чем меньше мусора, тем выше шанс пройти приёмку с первого поколения. Но не
жадничайте — карта с пустым срезом (весь проект) уверенно вычитывает из
репозитория то, что не угадать: например, карту фаз разработки по плану.

### 6. Best-of-N — самая дорогая ручка

Три варианта одной карты съели 23% счёта колоды из шести карт, и победил первый
же. Включайте точечно: там, где карта уже падала, а не по умолчанию.

### 7. Время в очереди не зависит от размера батча

| запросов | минут |
|---|---|
| 1 | 21.6 |
| 3 | 21.1 |
| 8 | 22.0 |

Провайдер съедает ~20 минут независимо от объёма. Следствие: **широкая колода
почти бесплатна по времени**. Не дробите работу на мелкие батчи — собирайте
широкое поколение.

## Цикл работы

```
/card ...          — набираете колоду (днём)
/deck              — смотрите состав, поколения, статусы
/submit @glm       — поколение уезжает; создаётся ветка morph/<deck-id>
/collect wait      — ждёте с прогрессом; или голый /collect — один опрос
/deck runs         — архив прогонов
```

- `/submit nogit` — прогон без git (для грязного дерева).
- `/deck reset` — выбросить состояние прогона, бэклог оставить.
- `/nightly` — вся колода одним блокирующим проходом.

**Прогон = ветка.** Каждая принятая карта — коммит с провенансом в трейлерах
(`Morph-Card`, `Morph-Model`, `Morph-Acceptance`, `Morph-Acceptance-Exit`).
Финальный коммит — колода и отчёт. Утром вы либо мержите ветку, либо выбрасываете
одной командой. На грязном дереве прогон не стартует — это защита, а не каприз.

## Чек-лист перед сабмитом

- [ ] У каждой карты есть `acceptance`, и она **запускается** (проверьте руками).
- [ ] Приёмка не противоречит инструкции.
- [ ] Приёмка `patch`-карты содержит полный прогон тестов.
- [ ] Меняете поведение — тест в `targets` той же карты, либо отдельной картой-судьёй.
- [ ] Карта не читает файл, который пишет соседняя карта того же поколения (иначе `depends_on`).
- [ ] Все пути в `context_slice` существуют или являются целью более ранней карты.
- [ ] Одна модель на колоду.
- [ ] Дерево чистое — или осознанный `nogit`.

## Как читать провал

| статус | что это значит |
|---|---|
| `failed after N attempt(s)` | приёмка не прошла N раз; смотрите `acceptance_output` в отчёте |
| `skipped (dependency X)` | зависимость упала; чините X |
| корректный код, но красная приёмка | **ваша** ошибка в критерии — проверьте его в песочнице руками |
| ответ оборван / пропущена цель | испорченный ответ; Морф не пишет такое на диск, карта уходит на перегенерацию |

Лимит перегенераций — 2 (итого 3 попытки). Вывод упавшей приёмки уезжает в
следующую попытку автоматически: голова и хвост, 4000 символов.
