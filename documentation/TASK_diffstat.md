# Задача для Морфа: дифф-статистика принятой карты

> Постановка для оркестратора. Написана в отдельной сессии, специально **без**

> Дата постановки: 17.09.2026. Исполнителю эту страницу в срез не класть.

Каждый токен, попавший в контекст оркестратора, был перечитан в среднем **66

кладёт себе в контекст**.

Сейчас, чтобы понять, что сделала принятая карта, оркестратор должен прочитать
файл целиком (`cards/store.py` — 15k токенов). Дифф той же карты — 30–80 строк,
около 1k. Разница 10–50x на каждое решение, и она умножается на 66.

Побочно это закрывает боль 4.2 (`Head_Pains.md`): исполнитель возвращает файл
целиком и может молча вычистить прозу — тесты этого не видят **по устройству**,
а `numstat` видит сразу.

Всё сырьё уже есть: каждая принятая карта — это один коммит с трейлером
`Morph-Card` (Фаза 7). Ничего нового добывать не надо, надо донести до отчёта.

## Контракт: что должно стать правдой

Ровно это, без вольностей в именах — по ним потом пишется потребитель.

### A. `cards/repo.py` — новая функция `diffstat`

```python
def diffstat(root: str, sha: str) -> List[dict]
```

* внутри — `git show --numstat --format= <sha>` через существующий `_git`;
* возвращает список в порядке git:
  `[{"path": str, "insertions": int | None, "deletions": int | None}, ...]`;
* бинарный файл git печатает как `-  -` — такие поля становятся `None`,
  а не нулями: «неизвестно» и «ноль» — разные факты;
* путь — как его печатает git, относительно корня репозитория;
* при ошибке git поднимает `GitError`, как все соседи по модулю.

### B. `cards/generations.py` — два поля в `CardOutcome`

```python
commit: Optional[str] = None        # sha коммита этой карты
diffstat: Optional[List[dict]] = None   # то, что вернул repo.diffstat
```

Оба со значением по умолчанию `None`, чтобы **ни одна** существующая точка
создания `CardOutcome` не менялась. Документировать в докстринге класса: поля
заполняются только для карты, которая стала коммитом (прогон в git-режиме).

### C. `cards/store.py` — сериализация

`_outcome_to_dict` пишет оба поля; `_outcome_from_dict` читает их через
`.get(...)` со значением `None`, чтобы `state.json` и `report.json`, записанные
**до** этой правки, продолжали читаться.

### D. `cards/store.py` — `make_card_committer` заполняет их

После успешного коммита (когда `sha is not None`):

```python
outcome.commit = sha
outcome.diffstat = repo.diffstat(root, sha)
```

Два требования, оба обязательны:

1. **Хук не имеет права падать.** Он уже это обещает в докстринге: карта,
   которая принята и лежит на диске, не должна отменяться из-за бухгалтерии.
   `GitError` здесь ловится, поля остаются `None`, в лог уходит одна строка.
2. **Мутация доезжает до диска сама**: `CardOutcome` — мутабельный dataclass,
   а оба маршрута прогона сохраняют исходы **после** срабатывания хука
   (`process_generation` → `_store_outcomes` в `collect_generation`;
   `run_deck` → `DeckResult` → `record_run`). Проверить тестом оба маршрута,
   отдельного кода для этого не писать.

### E. CLI — `/deck runs <deck-id>`

Голый `/deck runs` не меняется. С аргументом-идентификатором — покарточный вид
из архивного `report.json`, по строке на карту:

```
    <custom_id>   <status>   +<вставок> -<удалений>   <sha[:10]>   <пути>
```

* карта, у которой **удалений больше, чем вставок**, получает пометку в конце
  строки — это тот самый страж прозы, и это пометка, а не отказ;
* карта без коммита (прогон без git, или ничего не изменилось) печатает `-`
  вместо цифр, а не падает;
* неизвестный идентификатор — одна внятная строка и подсказка про голый
  `/deck runs`.

Строка `/help` про `/deck` дополняется новым аргументом.

## Приёмка

* каждая карта — своим тестовым файлом плюс **полный прогон**:
  `venv/bin/python -m pytest tests/ -q`;
* на момент постановки зелёных тестов **394**; после работы их должно стать
  больше, и ни одного упавшего;
* git-тесты в этом репозитории уже умеют временный репозиторий — смотреть
  `tests/test_repo.py` и `tests/test_run_git.py`, брать оттуда, а не изобретать.

## Ограничения, оплаченные вчерашним опытом

1. **Конверт карты — 20–60 строк правки существующего файла.** Замеренный
   конверт самого Морфа: +27/-1, +42/-0, +54/-0, +24/-1. Не влезает — делить
   карту, а не расширять срез (правило 8 скила).
2. **Карта аддитивна.** Удаления — красный флаг: та же боль 4.2, из-за которой
   вводится `numstat`.
3. **Код и его тест — одной картой** через `targets`.
4. **Не трогать** существующие докстринги и комментарии. Они здесь — половина
   ценности файла.
5. **Один файл — одна карта-владелец в поколении.** Морф теперь проверяет это
   сам (`/deck check`), но дешевле не создавать конфликт, чем разбирать отказ.
6. Срез называть явно. Пустой срез = весь проект: дорого и даёт
   предупреждение `implicit-read`.

## Предрегистрация прогнозов

Записано **до** прогона, чтобы результат нельзя было подогнать.

| величина | прогноз |
|---|---|
| карт в колоде | 4–6 |
| поколений | 2–3 |
| счёт исполнителя (OpenRouter) | < $0.50 |
| счёт сессии-оркестратора (Claude Code) | $2–4 |
| та же задача фронтир-моделью напрямую | $4–7 |
| карт, которым понадобится перегенерация | ≥ 1 |
| конфликтов `write-write` на префлайте | 0 |

**Проверяемое утверждение:** маршрут через Морфа обойдётся **дешевле половины**
прямого. Если нет — архитектура не окупается на этом классе задач, и это тоже
результат, ради которого стоило считать.

## Что записать по итогу

`/cost` в конце сессии-оркестратора плюс: число запросов, чтение кэша, средний
контекст на запрос, wall-time, время в очереди провайдера, число перегенераций,
итоговое число тестов. Этого хватит, чтобы посчитать главную метрику —
**стоимость сессии оркестратора на принятую карту**.

### Что опровергнуто

**Гипотеза «плохие результаты из-за слабой модели» — не подтвердилась.** Прогон
шёл на `glm-5.3-flash:batch`, на том же исполнителе, на котором раньше терялась
проза и горели чужие тесты. Здесь: пять карт из пяти с первой попытки, одно
удаление на весь прогон, правило 8 (большая карта не лечится контекстом) не
выстрелило ни разу. Изменились спецификация и разбивка колоды, а не модель.

**Экономическая посылка манифеста — половинная цена батча — нерелевантна.** Она
дала 3.5 цента из $4.13. Морф зарабатывает не на дешёвом токене, а на объёме
обвязки (тест/код = 3.8:1), на механическом качестве и на снятии витков
«правка-проверка» с фронтир-цикла.

### Приём, который стоит повторять

Чистую логику — в **новый** файл (`cards/runs_view.py`, 168 строк; новый файл
конвертом правки не ограничен), в большом файле оставить только проводку.
`flows/morph.py` на 1599 строк получил **+40 / −1** там, где в предыдущей колоде
сгорели 14 чужих тестов. Аддитивность применена к структуре, а не к тексту.

### Честная асимметрия

Спецификацию выше писал не тот оркестратор, который гонял колоду, а отдельная
сессия — и её токены в $4.13 не входят. Следующий замер будет чище, если
оркестратор получит одну строку цели и напишет себе контракт сам.
