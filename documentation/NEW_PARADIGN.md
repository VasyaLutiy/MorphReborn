# Новая парадигма: Морф как батч-оркестратор

> Русский нарратив-манифест исследования «Morph 2.0». Формальная
> англоязычная спецификация — в [`batch-orchestrator.md`](./batch-orchestrator.md).
> Это — серьёзная машина для серьёзных программистов, а не вайб-кодинг-агент.

## Почему именно Морф ложится на батчи без сопротивления

Батч-API (и у Anthropic — Message Batches, и у OpenAI — Batch API) имеют
одно жёсткое требование: каждый запрос должен быть **самодостаточным и
одноразовым**. Никакого интерактивного цикла, никаких tool-calls с ожиданием
ответа, никакой возможности «спросить уточнение». Ты отдаёшь JSONL с тысячей
запросов, ждёшь (обычно минуты-часы, дедлайн 24 часа) и получаешь тысячу
ответов — за **полцены**.

Агентский инструмент вроде Claude Code в этот формат не влезает в принципе —
его цикл интерактивен по своей природе. А вот морф — влезает как родной.
Смотри, что у Морфа уже есть:

- Каждый морф — **stateless one-shot**: свежий `LLMDialog`, собранный с
  диска, одна инструкция, один ответ, один файл. Это буквально формат
  батч-запроса.
- `JobScheduler` с очередью и слотами — это уже наполовину батч-оркестратор,
  он просто гоняет джобы в реальном времени вместо отправки пачкой.
- Мульти-процессорный fan-out (`@all`) — готовая семантика
  «один джоб → N запросов в батче».

То есть переделка — не смена парадигмы Морфа, а её *доведение до логического
конца*. **Морф всегда был батч-системой, которая притворялась чатом.**

## Аналогия с PDP-11 глубже, чем кажется

В эпоху батч-обработки была JCL — Job Control Language: мета-разметка на
колоде перфокарт, которая говорила машине, *что* это за джоб, какие ресурсы
ему нужны, куда класть результат. Мета-разметка к каждому батчу — это ровно
оно. Назовём это **morph card**:

```json
{
  "custom_id": "job-042-scheduler-tests",
  "meta": {
    "intent": "patch",
    "target": "scheduler.py",
    "context_slice": ["scheduler.py", "tests/test_scheduler.py",
                      "documentation/parallel-generate-scheduling.md"],
    "acceptance": "pytest tests/test_scheduler.py проходит",
    "model": "claude-sonnet-5",
    "variants": 3
  },
  "instruction": "добавь приоритеты джобов в очередь..."
}
```

## Новая архитектура: оркестратор-планировщик + батч-исполнители

Старый Морф решал проблему контекста грубой силой: весь проект в каждый
промпт. Это было честно для GPT-3.5, которая не умела просить файлы сама.
Новая схема — **инверсия**:

1. **Оркестратор** — фронтирная агентская модель в интерактивном режиме, но
   она *не пишет код вообще*. Она держит лёгкий контекст (карта репозитория,
   сигнатуры, граф зависимостей) и занимается одним: превращает user input в
   колоду morph cards. Ключевая интеллектуальная работа — **компиляция
   `context_slice`**: какие именно файлы нужны этому конкретному джобу. Это
   замена whole-project-context на «оркестратор знает, что положить в
   перфокарту».
2. **Батч-исполнители** — дешёвые запросы через Batch API. Каждый получает
   свой срез контекста + инструкцию, выдаёт морф. За полцены, параллельно,
   хоть тысячу штук.
3. **Цикл поколений**: батч вернулся → оркестратор прогоняет тесты/линтер по
   каждому морфу → упавшие джобы пересобираются в следующую колоду с
   добавленным контекстом ошибки → следующий батч. Это не агентский цикл
   per-file, это **nightly build для кодогенерации**. Вечером сгрузил бэклог
   изменений — утром разбираешь морфы.

И заметь: старый fan-out Морфа здесь мутирует во что-то мощное —
`variants: 3` в карте означает «сгенерируй три морфа этого файла», а
оркестратор потом выбирает лучший по тестам. Best-of-N становится почти
бесплатным при батч-скидке.

## Философский бонус

Батч-режим *принудительно возвращает дисциплину эпохи перфокарт*. Когда
ответ приходит через час, а не через секунду, ты не можешь вайб-кодить
итерациями «не то, переделай». Morph card обязана содержать полную
спецификацию: контекст, намерение, критерий приёмки. Машинное время снова
дороже человеческого раздумья — и это лечит ровно ту болезнь, за которую
сейчас ругают агентский кодинг. **PDP-11 как этическая позиция, а не только
как архитектура.**

Это тот же философский ход, что и whole-project context в Морфе 1.0
(см. [`modeling-approach.md`](./modeling-approach.md)): ограничение
инструмента — одновременно архитектурный стимул. Полный контекст толкал
кодовую базу к слабой связанности; батч-латентность толкает инженера к
полной, проверяемой спецификации.

## Чем это будет отличаться от Клод Кода

Вопрос, который задают первым: если Морф умеет планировать, исполнять и
проверять — чем он тогда не ещё один кодинг-агент? Отличие есть, и оно не в
качестве моделей, а в **устройстве цикла**.

|                           | чат-агент (Claude Code и родня) | Морф-как-агент          |
| ------------------------- | ------------------------------- | ----------------------- |
| ритм                      | синхронный, минуты              | асинхронный, ночь       |
| единица работы            | реплика в диалоге               | колода с приёмкой       |
| инструменты исполнителя   | shell, файлы, сеть              | **никаких**             |
| что доказывает корректность | твоё чтение диффа             | код возврата acceptance |
| что остаётся после        | история чата                    | колода и коммиты с провенансом |

Три следствия, ради которых всё и затевается.

**Замысел существует до кода и переживает его.** Колода — артефакт: её можно
прочитать, отревьюить, сдиффить, положить в репозиторий. У чат-агента «план»
живёт в контексте сессии и умирает вместе с ней; воспроизвести, почему файл
выглядит именно так, нельзя даже автору.

**Действие ограничено по построению, а не по инструкции.** Исполнитель не
имеет shell, сети и файловой системы. Он получает самодостаточный промпт и
возвращает текст одного файла (после Ф7 — набора файлов). Он физически не
может снести ветку, уронить прод или уйти гулять по интернету. Это не
политика безопасности, которую модель может обойти уговорами, — это форма
батч-запроса. Отсюда и сознательный **non-goal**: инструментов исполнителю не
давать никогда. Дать их — значит получить обычного агента с непредсказуемым
бюджетом и потерять разом и полцены батча, и механическую приёмку.

**Корректность доказывает машина.** Морф не спрашивает модель «ты уверен?» и
не полагается на то, что человек внимательно прочтёт дифф в шесть утра. Он
пишет вариант на реальный путь, гоняет команду, смотрит exit code и
**откатывает не прошедшее**. Карта без acceptance — это не карта, а пожелание.

Отсюда точная метафора: Морф — **не собеседник, а билд-система, в которой
рабочие суть языковые модели**. Колода — Makefile, acceptance — тест,
поколения — граф зависимостей, ночной прогон — ночная сборка. Вайб-кодинг это
импровизация в REPL; тут — CI, где программист формулирует проверяемое
задание вечером и принимает работу по зелёному прогону утром.

И честная граница: это **не замена** интерактивному агенту, а другой вид
животного. Всё, что требует живого диалога с кодом — разведка незнакомой
базы, «поправь опечатку», отладка по горячим следам, — остаётся за чат-агентом
и останется там навсегда: латентность батча несовместима с любопытством.
Морф берёт другое — **бэклог хорошо сформулированных изменений**, который
незачем держать в голове и дорого делать руками.

## Где будет больно (честно)

- **Компиляция `context_slice` — это и есть вся сложность проекта.** Если
  оркестратор ошибся срезом, исполнитель галлюцинирует ровно так, как
  описано в `modeling-approach.md`. Спасение: для мелких проектов fallback
  на старый добрый whole-project (при батч-скидке это дёшево), для крупных —
  слайсинг по графу зависимостей.
- **Латентность несовместима с «поправь опечатку».** Это инструмент для
  бэклога независимых изменений, не для интерактивной сессии. Честно
  позиционировать как nightly morphing.
- **Зависимые джобы в одном батче нельзя** — если джоб B правит файл,
  который генерит джоб A, они обязаны попасть в разные поколения.
  Оркестратору нужен топологический сорт колоды. (Существующий
  `JobScheduler` с pinned/rotation семантикой — концептуальная заготовка
  ровно этого.)

## Тезис рисёрча

**«Агент планирует, батч исполняет»** — и Морф как исторически первое
доказательство, что stateless one-shot морфинг вообще работает.
