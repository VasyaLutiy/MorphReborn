# Задача для Морфа: безголовая поверхность и вынос механики из модели

> Постановка для оркестратора. Разбивка на карты намеренно **не дана** — это
> работа, стоимость которой меряется.
>
> Дата постановки: 18.09.2026. Исполнителю эту страницу в срез не класть.

## Зачем это

Замер прогона 17.09 (`TASK_diffstat.md`, раздел «Факт»): сессия оркестратора
$4.06 против $0.07 исполнителю. Оркестратор — **98.3% счёта**, 47 запросов при
87k среднего контекста. Разбор по статьям показал, куда именно:

- **~15 запросов из 47 модель работала клавиатурой** — гоняла REPL через
  `printf ... | mrph`, по одной карте за запуск. Это ~$1.3, треть счёта, за
  печатание команд;
- `deck_collect` в MCP опрашивает батч **один раз** и отвечает «позови ещё
  позже» — то есть цикл опроса тоже модель, при очереди 20–40 минут.

Принцип, из которого растёт весь контракт:

> **Вызов, который делает модель, обязан соответствовать РЕШЕНИЮ, а не шагу.**

Мышление — декомпозиция, починка колоды, разбор отчёта. Механика — отправить,
дождаться, собрать, перегенерировать, интегрировать, закоммитить, заархивировать
— модели в цикле не требует вовсе. Все эти функции уже написаны в
`cards/store.py` и `cards/generations.py`; к ним просто нет двери для скрипта.
Единственный вход сегодня — REPL, спроектированный для человека с клавиатурой.

## Контракт: что должно стать правдой

### A. Точка входа: `mrph <подкоманда>`

`bin/mrph` без аргументов запускает REPL ровно как сейчас — поведение человека
не меняется ни на байт. С аргументами уходит в безголовый путь.

Разбор `sys.argv` происходит **до** импорта `flows.morph`: безголовый путь не
имеет права тащить за собой консольного бота, его зависимости и побочные
эффекты. Реализация живёт в новом модуле (`cards/cli.py` или соседний), и на
него распространяется правило: `cards` не импортирует `flows`.

### B. Правило вывода, несущее всю конструкцию

* **stdout — ровно один JSON-документ**, всегда, включая ошибки. Ничего кроме.
* **stderr — человеческий лог.** Всё, что store-функции пишут через `log=`,
  уходит туда; передавать им логгер в stderr, а не `print`.
* ни одного интерактивного вопроса, ни одного чтения stdin.
* флаг `--pretty` включает отступы; без него — компактно, одной строкой.

Проверка, которой этот пункт меряется: `json.loads(stdout)` обязан пройти на
**любом** исходе любой подкоманды.

### C. Коды возврата

| код | значение |
|---|---|
| 0 | сделано; для `run` — все карты приняты |
| 1 | завершилось, но есть провалившиеся или пропущенные карты |
| 2 | **отказ до траты денег**: конфликт владения, грязное дерево, `StoreError` |
| 3 | транспорт/провайдер: батч отвергнут, ожидание исчерпало таймаут |
| 4 | ошибка употребления: нет файла, битый JSON, неизвестный процессор |

Ошибочный документ в stdout имеет вид `{"error": {"code": <int>, "kind":
"<класс>", "message": "<текст>"}}`.

### D. Подкоманды

| команда | делает | печатает |
|---|---|---|
| `mrph deck add --file <path>` | добавляет **массив** карт (или один объект) одной атомарной операцией | `{"added": ["id", ...], "hazards": [...]}` |
| `mrph deck check` | конфликты владения файлами | `{"cards": N, "errors": N, "warnings": N, "hazards": [...]}` |
| `mrph deck status` | состав бэклога, поколения, статусы | см. ниже |
| `mrph submit [--processor X] [--nogit]` | отправляет текущее поколение и выходит | `{"submitted": bool, "generation": N, "total": M, "batch_id": ..., "cards": [...], "skipped": [...]}` |
| `mrph collect [--wait] [--timeout S]` | собирает; с `--wait` держит до конца поколения | `{"in_progress": bool, "generation": N, "total": M, "phase": ..., "outcomes": {...}}` |
| `mrph run [--processor X] [--nogit] [--timeout S]` | **весь прогон блокирующе**: префлайт → поколения → перегенерации → архив | отчёт прогона целиком |
| `mrph report [<deck-id>]` | архивный отчёт; без аргумента — последний | `RunReport.to_dict()` как есть |

Формы, которые надо зафиксировать точно:

* **hazard** — `{"kind", "severity", "left", "right", "paths": [...],
  "generation": N|null, "message"}` (поля берутся у `cards.hazards.Hazard`,
  `message` — из его `message()`);
* **deck status** — `{"empty": bool, "phase": str, "current_generation": int,
  "generations": [[id, ...], ...], "cards": [{"custom_id", "status"}, ...]}`;
* **outcome** — та же форма, что уже пишется в `report.json`
  (`cards.store._outcome_to_dict`), включая `commit` и `diffstat`. Второй
  сериализации для одной сущности быть не должно.

`deck add` атомарен: карты добавляются все или ни одной, и конфликты владения
**сообщаются, но не отказывают** — отказывает префлайт прогона. Это уже
поведение `/card`, менять его нельзя.

### E. Ожидание, которое переживает сеть

`--wait` и `run` опрашивают батч сами. Сегодня один моргнувший GET рвёт
ожидание — `Head_Pains.md` 2.5, приоритет №1 в собственной таблице: обрыв на
1 ч 42 мин из-за одного таймаута.

* повтор с экспоненциальным отступом (старт ~5 с, потолок ~120 с),
* прекращать **только** по неустранимой ошибке или по исчерпанию `--timeout`
  (по умолчанию 6 часов на прогон),
* исчерпанный таймаут — это код 3 и состояние, которое **можно собрать
  позже**: незавершённый прогон обязан остаться коллектируемым, никакого
  обрыва посреди приёмки,
* обёртка живёт в раннере, а не внутри провайдерского бэкенда: бэкенд остаётся
  тупым.

### F. `run` — это ночной цикл целиком

Префлайт владения (отказ кодом 2 до ветки и до денег) → поколение за поколением
через существующий `run_deck` → перегенерации → архив → коммиты. Новой логики
прогона не писать: она есть.

### G. Ничего не ломать

REPL, MCP-сервер и существующие 431 тест остаются как есть. Безголовый путь —
добавление, а не переделка.

## Приёмка

* каждая карта — своим тестовым файлом плюс полный прогон:
  `venv/bin/python -m pytest tests/ -q`;
* тесты гоняют CLI **через функцию** (`main([...])`), не через подпроцесс, с
  подставным бэкендом: перехватить stdout, убедиться, что он парсится как JSON,
  проверить код возврата;
* на момент постановки зелёных тестов **431**; после работы больше и ни одного
  упавшего;
* обязательный тест на правило B: при любой ошибке stdout всё равно парсится.

## Ограничения, оплаченные опытом

1. **Конверт правки существующего файла — 20–60 строк.** Замер вчерашнего
   прогона: +11, +36, +40, +70. Не влезает — делить карту.
2. **Карта аддитивна.** Удаления — красный флаг (боль 4.2). За весь вчерашний
   прогон удаление было одно.
3. **Приём, который вчера сработал:** чистая логика — в **новый** файл (новый
   файл конвертом не ограничен), в большом файле остаётся проводка.
   `flows/morph.py` на 1599 строк получил +40/−1 там, где в позапрошлой колоде
   сгорели 14 чужих тестов.
4. **Код и его тест — одной картой** через `targets`.
5. **Один файл — одна карта-владелец в поколении** (`/deck check`).
6. Срез называть явно; пустой = весь проект, дорого и даёт `implicit-read`.
7. Приёмка обязана **печатать диагноз** (боль 4.1): `assert` без сообщения и
   `sys.exit(1)` сжигают все три попытки вслепую.

## Что намеренно НЕ задано

Разбивка на карты, их число и границы, срезы, порядок, формулировки приёмок,
имена тестовых файлов, внутреннее устройство разбора аргументов.

## Что вне области этой колоды

* перекройка MCP под решения (`deck_propose` массивом, `run_start`,
  `run_status`, `run_report`, удаление `deck_collect` как поллера) — **следующая
  колода**, она опирается на эту;
* бюджетный ограничитель по деньгам и упаковка под `cron` — после неё;
* никаких изменений в поведении REPL.

## Предрегистрация прогнозов

| величина | прогноз |
|---|---|
| карт в колоде | 7–12 |
| поколений | 2–3 |
| счёт исполнителя | < $1.00 |
| счёт сессии-оркестратора | $3–6 |
| карт с перегенерацией | 1–3 |
| конфликтов `write-write` на префлайте | 0 |
| тестов | > 431 |

**Главное проверяемое утверждение — про компаундинг, а не про общий счёт:**

> **доллар за принятую карту окажется ниже вчерашних $0.83.**

Вчера: $4.13 на 5 карт. Больше половины запросов ушло на то, что не растёт с
числом карт (базовая линия, идиома карты, радиус правки, формат отчёта, сбор,
прогон тестов, слияние, отчёт). Если гипотеза «фиксированная часть
амортизируется» верна — на 7–12 картах цена карты обязана упасть. Если не
упадёт, значит масштабирование колоды не работает, и это меняет весь план.

Второе, послабее: **доля карт, прошедших с первой попытки, удержится на 85%+**
при вдвое большей колоде.

### Главное утверждение — НЕ проверено

Замер компаундинга (`$ за принятую карту ниже вчерашних $0.83`) **недействителен**:

Одна грязная точка против гипотезы, не за неё.

### Что зато устояло на двух колодах подряд

| | колода 17.09 | колода 18.09 |
|---|---|---|
| **$ за 1000 доставленных строк** | **$2.38** | **$2.74** |
| $ за принятую карту | $0.83 | $1.10 |
| средний контекст оркестратора | 87k | **169k** |

**Методологическая поправка: мы предрегистрировали не ту величину.** «Доллар за
карту» уплыл на 33%, «доллар за строку» — на 15%, потому что карты разного
размера (347 строк вчера, 403 сегодня). Стабильная метрика — **за строку
доставленного кода**, и в следующей предрегистрации должна стоять она.

Экономия против прямой работы фронтир-модели (~$4.7 за 1000 строк по замеру
17.09) — **40–45%**, та же цифра, что вчера, воспроизведённая на колоде вдвое
больше и на скверном прогоне.

И **«глубина платит дважды» подтвердилась жёстче:** 87k среднего контекста на
двух поколениях против 169k на семи.

### Настоящий улов — два дефекта

1. **Обрезка обратной связи убивает карту** (`Head_Pains.md` 2.13, новый
   приоритет №1). `cli-run-cycle` сожгла все три попытки, потому что обрез в
   4000 символов пришёлся ровно на `intent must be one of ` — список допустимых
   значений остался в вырезанной середине. Модель трижды получила вопрос без
   ответа; каскадом ушли две зависимые карты. Обход нулём строк кода:
   `-q --tb=line` (5 полных диагнозов вместо одного погребённого).
2. **Достаточность среза.** Срез обязан содержать форму, которую карта должна
   *сконструировать*, а не только вызвать. Естественный эксперимент внутри одной
   колоды: две карты без `cards/schema.py` упали одинаково, карта, чьи
   конструируемые формы были в срезе, прошла с первой попытки, и та же упавшая
   карта с добавленным `schema.py` — тоже с первой.

Оба записаны в `Morph_SKILL.md` и `TASK_TEMPLATE.md`, чтобы следующая колода их
не повторила.
