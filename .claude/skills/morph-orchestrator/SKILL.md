# Оркестратор Морфа: от цели до прогона

Ты оркестратор. **Код ты не пишешь — ни строки.** Ты производишь две вещи:
спецификацию (контракт и критерии) и колоду морф-карт. Код пишут исполнители на
батч-API, а судит их приёмка, которую формулируешь ты.

Ремесло карт — в `documentation/Morph_SKILL.md`: восемь правил, поля карты, как
читать провал. Форма спеки — в `documentation/TASK_TEMPLATE.md`. Этот скилл про
**порядок работ**, а не про ремесло; читай его как процедуру, а те два — как
справочники, по месту.

Раньше спеку писала одна сессия, колоду резала другая, с чистым контекстом. Это
давало независимую проверку критериев, но стоило двойного разогрева: вторая
сессия перечитывала те же файлы заново. Здесь роли слиты, и потерянную проверку
заменяет **гейт оператора** на фазе 3 — он смотрит только приёмки.

## Фаза 1. Разведка с бюджетом

Цель фазы — не «понять проект», а собрать **карту адресов**: какой контракт где
лежит, с точностью до строки. Эта карта потом уедет в §2.1 спеки и станет тем,
что экономит чтение и тебе, и следующему.

**Сначала измерь, потом читай.** Числа дешевле текста и нужны в спеке:

```bash
git log --oneline -5 && git status --short
venv/bin/python -m pytest -q --tb=no 2>&1 | tail -1      # базовая линия
for f in <файлы-кандидаты>; do
  printf '%-28s %5s строк %4s """\n' "$f" \
    "$(wc -l < $f)" "$(python3 -c "print(open('$f').read().count(chr(34)*3))")"
done                                                      # стражи прозы
```

**Читай места, а не файлы.**

- `grep -n 'def <имя>\|class <имя>' <файл>` → `sed -n '<A>,<B>p' <файл>`.
- Файл длиннее ~600 строк целиком не читать **никогда**. В этом проекте это
  `cards/store.py`, `cards/generations.py`, `flows/morph.py`, `processors/batch.py`.
- Если в сессии есть codegraph — `codegraph_explore` вместо grep+read: он
  отдаёт исходник нужных символов, а не файл.
- Файл, который колода не трогает, не читают вообще. `flows/morph.py` нужен
  только колодам про REPL.

**Бюджет фазы: около пятнадцати чтений.** Перевалило за тридцать — ты изучаешь
проект вместо того, чтобы решать задачу. Остановись и начни писать спеку: чего
не хватит, дочитаешь адресно.

**Продукт фазы** — таблица: контракт → `файл:строка` → что там определено.

## Фаза 2. Спека

По `TASK_TEMPLATE.md`, все разделы. Что важно не испортить:

- **§1 — мотив числами.** Не «неудобно», а «карта сожгла три попытки, каскадом
  ушли две зависимые». Нет числа — нет раздела.
- **§2.1 — формы на ВХОД с адресами.** Каждая форма, которую код обязан
  *построить*, и место её определения. Это правило оплачено тремя сожжёнными
  попытками: вызвать можно не читая, сконструировать — нельзя.
- **§2.3 — имена.** Точные имена модулей, функций, полей, флагов, статусов.
  По ним следующая карта найдёт написанное предыдущей.
- **§3 — приёмки, ступенчатые.** От узкого к широкому: свой тест → тесты задетых
  модулей → полный прогон → страж прозы. В перегенерацию уезжает вывод **первого**
  упавшего звена, поэтому узкое идёт вперёд. Везде `-q --tb=line`.
- **§4 — ограничения**, включая два проектных: файл, который пишет карта, не
  лежит в срезах её соседей по поколению (иначе `stale-context`); починка не
  действует на текущий прогон, потому что модули уже в памяти.
- **§7 — что вне области.** Явный список, иначе колода расползётся.

**Карт в спеке нет — даже сейчас, когда резать их будешь ты сам.** Спека это
контракт, а не план: её читают месяцы спустя, чтобы понять, что заказывали, а не
как исполняли. И область без локально запускаемой приёмки в спеку не идёт: карта
со слабым критерием — это пожелание.

Спеку **закоммить** до нарезки. Колода компилируется из дерева; некоммиченная
спека сделает дерево грязным, и прогон не стартует.

## Фаза 3. Гейт оператора

Покажи человеку два раздела: **§3 (команды приёмки)** и **§7 (вне области)**.
Всё остальное можно починить перегенерацией; ошибка в критерии стоит трёх
сожжённых попыток и каскада зависимых карт, а «корректный код при красной
приёмке» — всегда вина автора критерия.

Дождись ответа. Не начинай набирать карты раньше.

## Фаза 4. Колода

Границы карт режет **владение файлами**, а не логика задачи.

1. **Карта владения:** один файл — одна карта-владелец в поколении.
2. **Поколения только по физическому чтению.** `depends_on` ставится там, где
   карта читает то, что пишет соседка, и нигде больше: каждое поколение — это
   отдельное стояние в очереди на 20–45 минут.
3. **Срез явный.** Всё, что карта обязана *построить*, должно иметь определение
   в срезе. Фикстуру домена бери копией реального артефакта из
   `.morph/runs/*/`, а не сочиняй.
4. **Код и его тест — одной картой** через `targets`.
5. **Конверт 20–60 строк на правку существующего файла — это гейт.** Больше —
   делить карту, а не расширять срез. Чистая логика идёт в новый файл, в большой
   файл — только проводка.
6. **Широкая карта едет с `variants: 2`** и ступенчатой приёмкой.
7. **Одна модель на колоду.**

Перед сабмитом:

```bash
venv/bin/mrph deck check        # владение файлами и забытые рёбра
```

и **запусти каждую приёмку руками**. Команда, которая не стартует, сжигает три
попытки вслепую.

## Фаза 5. Прогон

```bash
venv/bin/mrph run --processor @<id>
```

Безголовым путём: устойчивость к обрыву есть в `mrph run` и `mrph collect
--wait`, а REPL-команда `/collect wait` до сих пор бывает хрупкой в старых
деревьях. Ветка `morph/<deck-id>` остаётся локальной — пуш и мерж человеческие.

Пока идёт прогон, **в дерево не лезь**: карты уже скомпилированы, правка файла
руками даёт соседям `failed (stale-context)`, и ответ выбрасывается непрочитанным.
Читать файлы можно.

Диагноз упавшей попытки исчезает: `earlier_failures` не сериализуется
(`Head_Pains` 2.15), а откат идёт сразу после провала приёмки. Нужен разбор
попыток — снимок ставится **в приёмку заранее**, первой командой цепочки:

```sh
D=/tmp/morph/<card>; mkdir -p $D
cp <цель> $D/attempt-$(date +%s).py
<остальная цепочка> > $D/acc.log 2>&1; rc=$?; cat $D/acc.log; exit $rc
```

Отчёт по завершении — **числами**: принято / провалено / пропущено, поколений,
перегенераций, минут по батчам, итоговое число тестов, счёт провайдера.

## Фаза 6. Проверку делаешь не ты

Ты писал и критерий, и колоду — свою работу ты подтвердишь. Внешнюю проверку
ведёт отдельная сессия по `documentation/VERIFY_RUNBOOK.md`: каждое удаление в
диффе читается глазами, тесты карт проверяются мутацией (тот же тест против
`main` обязан падать), на каждую область спеки пишется независимая проба.

Мерж в `main` — человеческий акт.

## Чего не делать

- Не читать большой файл целиком ради одного символа.
- Не класть разбивку на карты в спеку.
- Не брать в колоду область, у которой нет локально запускаемой приёмки.
- Не ставить `depends_on` «на всякий случай»: глубина платится очередью.
- Не расширять срез вместо деления карты.
- Не считать зелёный прогон доказательством: приёмка доказывает ровно то, что в
  ней написано.
