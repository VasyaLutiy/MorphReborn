## 1. Что это

Оркестратор пакетной генерации кода. Человек (или агент) производит
**спецификации** — морф-карты; код пишут исполнители на батч-API провайдера.
Морф компилирует карты в промпты, отправляет их одним батчем, проверяет ответы
приёмочной командой и превращает принятые в коммиты.

Ключевая асимметрия: контекст достаётся исполнителю, оркестратору — намерения и
доказательства. *Замер 17.09:* в батч из семи запросов уехало 641 916 символов
исходников (≈146 500 входных токенов), из них инструкции оркестратора — 6 217
символов, **0.97%**.

## 2. Как запустить

Зависимости разъехались по двум питонам, и это главная засада на старте:

| | venv в scratchpad | системный `/usr/bin/python3` (3.9) |
|---|---|---|
| `openai`, `python-dotenv` | да | нет |
| `pysyun` (консольный бот) | нет | да (`~/Library/Python/3.9/lib/python/site-packages`) |
| `pytest` | нет | да |

Рабочая связка — venv плюс системный site-packages в `PYTHONPATH`:

```bash
cd /Users/kyrylo/Documents/Pers/python_gptmorph_cli
PYTHONPATH=.:/Users/kyrylo/Library/Python/3.9/lib/python/site-packages \
  <venv>/bin/python bin/mrph
```

`PYTHONPATH=.` обязателен: `bin/mrph` импортирует `settings` и `flows.morph` из
корня проекта. Приёмочные команды запускаются отдельным процессом и зовут
`python3` из `PATH` — то есть системный, где pytest есть.

Неинтерактивно команды подаются на stdin:

```bash
printf '/deck\n/quit\n' | PYTHONPATH=... <venv>/bin/python bin/mrph
```

`/card` читает JSON **следующей строкой** после самой команды.

### Процессоры в `.env`

```
MRPH_PROCESSOR_<id>_TYPE=openrouter|openai|anthropic|llama_cpp|ollama
MRPH_PROCESSOR_<id>_MODEL=<слаг>
MRPH_PROCESSOR_<id>_API_KEY=<ключ>
MRPH_PROCESSOR_<id>_BASE_URL=<для openai-совместимых узлов>
```

Обращение — `@<id>`: `/submit @glm`, `/generate @a,@b`, `@all`.

## 4. Морф-карта

```json
{
  "custom_id": "fix-retry-idempotence",
  "intent": "patch",
  "targets": ["cards/store.py", "tests/test_store.py"],
  "context_slice": ["cards/generations.py"],
  "acceptance": "python3 -m pytest tests/test_store.py -q && python3 -m pytest -q",
  "variants": 1,
  "depends_on": [],
  "model": null,
  "instruction": "..."
}
```

| поле | смысл |
|---|---|
| `custom_id` | имя джоба, `[A-Za-z0-9._-]` |
| `intent` | `generate` \| `patch` \| `todo` |
| `target` / `targets` | ровно одно из двух; `targets` — changeset, пишется атомарно |
| `context_slice` | какие файлы показать. **`[]` — весь проект**, а не «ничего» |
| `acceptance` | shell-команда, **exit 0 = принято** |
| `variants` | best-of-N, побеждает первый прошедший приёмку |
| `depends_on` | рёбра графа; разносит карты по поколениям |
| `model` | хинт; **одна модель на батч** — смешанная колода не уедет |
| `instruction` | что и зачем. «Как» решает исполнитель |

Хранится в `.morph/deck.json`; `context_slice` и `depends_on` попадают в
`meta` (`cards/store.py:148`, `:158`) и, значит, в архив прогона.

## 5. Конвейер: от `/card` до коммита

```
/card ──► DeckStore.add_card            (cards/store.py:261)
          └ валидация схемы + колоды    (cards/schema.py, cards/deck.py:64)

/submit ─► split_into_generations       (cards/generations.py:68)
          ├ создание ветки morph/<id>   (cards/repo.py:196)
          ├ compile_deck                (cards/compiler.py:314)
          │   ├ _resolve_slice          (cards/compiler.py:155)  ← что карта увидит
          │   ├ _context_messages       (патч шлёт цели как "Original file")
          │   └ serialize_<провайдер>
          └ backend.submit              (processors/batch.py)
                → .morph/state.json: phase=submitted, batch_id

/collect ► backend.status               (один опрос)
          └ collect_generation          (cards/store.py:1221)
              ├ backend.collect         (результаты инлайн у OpenRouter)
              ├ запись файлов + ensure_parent_dir (cards/generations.py:436)
              ├ verify_card             (cards/acceptance.py:308)
              │   ├ зелено → on_accepted → commit_paths (cards/repo.py:267)
              │   └ красно → откат файлов, перегенерация (лимит 2)
              └ конец колоды → архив .morph/runs/<id>/ + финальный коммит
```

Важные свойства конвейера:

- **Приёмка не уезжает в промпт.** Проверено грепом по `cards/compiler.py`:
  поля `acceptance` в сообщениях нет. Исполнитель не может подогнаться под
  критерий, зато вывод *упавшей* приёмки уходит в следующую попытку (голова и
  хвост, 4000 символов, `cards/acceptance.py:75 clip_output`).
- **Компиляция побайтово воспроизводима** — на это есть тест
  `tests/test_compiler.py:131`. Любая врезка, делающая промпт зависимым от
  внешнего изменяемого состояния, ломает эту гарантию.
- **Патч-карта получает цели как «Original file»** и не дублирует их в срезе
  (`skip_target`). Если цели нет на диске — она просто не показывается, поэтому
  карта вида «пропатчить модуль и создать его тест» выразима.
- **Файлы пишутся до приёмки и откатываются при провале**
  (`_capture_originals` / `_restore_originals`). Каталоги, созданные по пути,
  **остаются намеренно** — удаление гонялось бы с чужой записью
  (`cards/generations.py:453`, «Rollback note»).

## 6. Граф зависимостей

Отдельного объекта «граф» нет: рёбра лежат в `depends_on` карт.

| функция | что делает |
|---|---|
| `cards/deck.py:88 _check_dependencies_exist` | каждая ссылка указывает на карту в колоде |
| `cards/deck.py:100 _check_acyclic` | DFS с трёхцветной разметкой; падает с `dependency cycle: 'a' -> 'b' -> 'a'` |
| `cards/generations.py:68 split_into_generations` | укладка по **длиннейшему пути**, мемоизация |

Сохранённое в карте поле `generation` игнорируется — побеждает вычисленное,
карты не мутируются. Внутри поколения сохраняется порядок колоды, поэтому
приёмка каждой следующей карты видит на диске результат предыдущей.

Каскад отказов: упавшая зависимость даёт `skipped (dependency X)`
(`cards/generations.py:595`).

**Чего граф не делает:** рёбра только явные. Морф не выводит зависимость из
того, что карта A пишет файл, который карта B держит в `context_slice`. Планировка
колоды по владению файлами — ручная работа оркестратора.

**Команда `/graph` к этому отношения не имеет** — она досталась от Morph 1.0 и
рисует Graphviz диалогового флоу самого бота. На показе не использовать.

## 7. Приёмка

`cards/acceptance.py:175 run_acceptance` — команда, `cwd=root`, таймаут 300 с.
Контракт один: **exit 0 = принято**.

Из этого следует, что в приёмку встраивается что угодно, возвращающее код
выхода, — без единой правки в Морфе. Проверенные на практике звенья:

```
"acceptance": "<страж прозы> && python3 -m pytest <новый тест> -q && python3 -m pytest -q"
```

- **Страж регрессии** (полный прогон) — обязателен для `patch`-карты.
  *Замер 17.09:* карта `deck-clear-command` написала себе зелёный тест и сломала
  14 чужих; поймал именно полный прогон.
- **Страж прозы** — `python3 -c "import sys;s=open('<файл>').read();sys.exit(0 if s.count(chr(34)*3)>=<N> else 1)"`.
  Нужен потому, что тесты структурно слепы к удалённой документации (см. «Замеры»).
- **Ревьюер-гейт** — внешний скрипт, судящий дифф фронтир-моделью. См. §11.

Лимит перегенераций — 2 (итого 3 попытки).

## 8. Git-слой

- Прогон = ветка `morph/<deck-id>`, отведённая **от текущей ветки**, а не от main.
- Принятая карта = коммит, стейджатся **только её пути** (`git add -- <paths>`,
  `cards/repo.py:297`), с трейлерами:

```
Morph-Card: <custom_id>
Morph-Model: <id процессора>
Morph-Acceptance: <команда>
Morph-Acceptance-Exit: 0
```

- Конец прогона = коммит `.morph/runs/<deck-id>/{deck.json,report.json}`.
  Колода в архиве содержит инструкции и критерии целиком — ветка самодостаточна.
- **Колода попадает в git только в конце.** Во время прогона она живёт в
  `.morph/deck.json`, который под `.gitignore`. Если машина умрёт посреди ночной
  колоды, спецификации незавершённых карт в git не окажется.
- `.gitignore` обязан иметь именно такой вид:

```
.morph/*
!.morph/runs/
```

  Git не заходит внутрь исключённого каталога, поэтому `.morph/` + `!.morph/runs/`
  **не работает**.

- На грязном дереве прогон не стартует. Выходы: `git stash -u` или
  `/submit nogit` (без ветки и коммитов, морфы всё равно ложатся в дерево).

**Параллельные прогоны.** `.morph` одноместный, поэтому два прогона в одном
рабочем каталоге невозможны. Рабочий приём — `git worktree`: ветки живут в одном
`.git` и сравниваются одним `git diff`, а `.env` копируется в новый каталог руками
(он под `.gitignore`).

## 9. Бэкенды и провайдеры

| класс (`processors/batch.py`) | особенности |
|---|---|
| `OpenAIBatchBackend` | загрузка JSONL, `batches.retrieve`, скачивание файла результатов |
| `AnthropicBatchBackend` | `client.messages.batches` |
| `OpenRouterBatchBackend` | **без SDK**: POST всей колоды инлайн на `/api/beta/batches`, результаты инлайн в том же ответе на опрос |
| `LocalBatchBackend` | эмуляция батча поверх `scheduler.JobScheduler` — «ведомственная ЭВМ» из локальных узлов |

Особенности OpenRouter, оплаченные временем:

- Порядок ключей в теле обязан быть `endpoint` → `model` → `requests` — сервис
  разбирает поток и иначе отвечает 400.
- Успешная отправка — **202**, статус `validating`.
- Есть окно read-after-write: 404 сразу после сабмита трактуется как «ещё не
  видно», но только для id, который отправил этот же экземпляр.
- **Каталог врёт.** `/api/v1/models` показывает `:batch`-слаги с ценами для
  моделей, у которых батч-эндпоинта нет. Замер 17.09: у Anthropic из всего ряда
  работал только `claude-opus-5:batch`; `sonnet-5`, `sonnet-4.6`, `haiku-4.5`,
  `opus-4.8` отвечают `does not have a :batch endpoint`. У Google работают все
  проверенные. **Слаг проверяйте пробником до того, как ставить в `.env`:**

```bash
curl -s -X POST -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"endpoint":"/v1/chat/completions","model":"<слаг>","requests":[{"custom_id":"p","body":{"messages":[{"role":"user","content":"ok"}],"max_tokens":8}}]}' \
  https://openrouter.ai/api/beta/batches
```

- Батч может быть отвергнут **верхним** провайдером уже после приёма: статус
  становится `failed`, а причина лежит в `error.message` объекта батча.

**Очередь.** Одна и та же карта, разные модели:

| модель | запросов в батче | очередь |
|---|---|---|
| `openai/gpt-5.6-luna:batch` | 2 | 6 мин 20 с |
| `z-ai/glm-5.3-flash:batch` | 1 | 37 мин 54 с |

запросов приехали за то же время, что один. Широкая колода почти бесплатна по
времени; платит за время **глубина** — каждое поколение это отдельное стояние.

**Сохранность чужого кода.** Та же карта, тот же файл (678 строк, 104 строки
прозы), разные модели:

| модель | строк после | строк прозы | дифф | приёмка |
|---|---|---|---|---|
| luna | 506 | **18** | 226 вставок, **305 удалений** | зелёная, 331 тест |

Тесты обе прошли. **Тесты структурно слепы к удалённой документации** — отсюда

Карта средней тяжести — $0.007; тяжёлая колода целиком — около $0.05; весь день
работы (шесть принятых карт) — около $0.15.

## 11. Внешние расширения (проверены, в код не врезаны)

### Ревьюер-гейт

Скрипт, судящий **дифф** фронтир-моделью и возвращающий 0/1. Встраивается
звеном в `acceptance`, Морф менять не нужно. Прототип:
`scratchpad/review_gate.py`.

*Замер:* на luna-диффе — `fail` с пятью точными находками (включая удалённый
`import io` и комментарий с пометкой «Do not delete»); на glm-диффе — `pass`.
Пять прогонов, ни одного разногласия. Цена $0.03–0.08 за карту.

Вопрос судье должен быть **узким и проверяемым** («удалено ли то, чего не
просили»), а не «хорош ли код»: приёмка — закон, и стохастический судья на
широком вопросе превращает её в лотерею.

### codegraph

`@colbymchenry/codegraph`, индекс строится за 256 мс (40 файлов, 1 411 узлов,
3 784 ребра).

| запрос | результат |
|---|---|
| `impact <символ>` | **работает**, включая тестовые файлы |
| `callers <функция>` | **работает** сквозь файлы |
| `callers <класс>` | пусто — класс не «вызывают», нужен `impact` |
| `affected <файл>` | **пусто даже там, где тесты очевидно задеты** — в приёмку не ставить |

*Замер предсказательной силы:* из четырёх провалов первой попытки тяжёлой колоды
предупреждение по радиусу поражения попадало **в один** (`deck-clear-command`,
91 символ, задеты `test_flows_transitions.py` и `test_run_git.py` — ни один не
был в срезе). Два провала — модель написала тест, не согласующийся с собственным
кодом; граф тут бессилен.

**Куда врезать, если врезать:** не в `_resolve_slice` (сломает воспроизводимость
компиляции и провенанс), а в **рождение карты** — вывести срез и записать его в
`context_slice`, чтобы он попал в архив. Плюс читающее предупреждение в
`build_submit_transition` (`flows/morph.py:1068`) перед вызовом
`submit_generation` (`:1094`).

## 12. Известные дефекты и статус

Починено самим Морфом 17.09 (ветка `morph/20260917-174646-f718dfe2`):

- отказ провайдера показывается оркестратору, а не съедается молча;
- диагностика упавшей попытки переживает карту, принятую со второго раза;
- `/deck clear` — выбросить бэклог из CLI;
- внятная ошибка на каталожный слаг без батч-эндпоинта.

Открыто:

- **`/collect wait` выходит из цикла по одному сетевому таймауту.** Замер: обрыв
  на 1 ч 42 мин ожидания из-за одной GET-ки. Для ночной колоды критично:
  нужен повтор с отступом, а прекращать — только по неустранимой ошибке.
- **Колода не в git до конца прогона** (см. §8).
- **Приёмка без обратной связи бесполезна для перегенерации.** Карта
  `demo-script-truth` сожгла три попытки на критерии из `grep`, который при
  провале не печатает ничего: `acceptance_output` — пустая строка. Критерий
  обязан не только отличать сделанное от несделанного, но и говорить, что не так.
- **Нет команды править карту до сабмита** — только добавить.
- **`documentation/Phase7_demo_testing.md` содержит две неточности:** такт 6
  утверждает, что каталог упавшей карты отсутствует (он остаётся пустым,
  намеренно), и очередь названа константой в ~20 минут.

## 13. Грабли, собранные лбом

1. **Пустой `context_slice` — это весь проект.** Карта с пустым срезом неявно
   читает цели всех соседей по поколению.
2. **Две карты не должны писать один файл в одном поколении** — планируйте
   колоду по владению файлами, иначе последняя затрёт первую.
3. **Одна модель на колоду** — `model` в OpenRouter-батче поле уровня батча.
4. **На грязном дереве прогон не стартует.** Индекс codegraph (`.codegraph/`),
   временные файлы и прочий мусор делают дерево грязным — держите их вне
   рабочего каталога или в `.gitignore`.
5. **`/deck reset` не чистит бэклог**, он сбрасывает состояние прогона. Для
   очистки — `/deck clear` (появилась 17.09) или удаление `.morph/deck.json`.
6. **Провал батча ≠ провал карт.** Если все карты упали «после 1 попытки» без
   причины — смотрите объект батча у провайдера, там `error.message`.
7. **Best-of-N включайте точечно.** Замер из Morph_SKILL: три варианта одной
   карты съели 23% счёта колоды из шести, победил первый.
